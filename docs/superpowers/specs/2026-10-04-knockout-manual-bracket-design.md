# 淘汰赛手动落位编排（设计）

- 日期：2026-10-04
- 状态：设计已逐节获批（用户批准）；spec 审阅后补齐占位数据通路、决赛归属与结构变化语义（§3.2–3.5），待用户复看
- 来源：脑暴请求「淘汰赛编排，不要自动生成赛程，仍采用点选配对，并且赛程页展示时首回合次回合分开」

## 1. 背景与目标

现状：淘汰赛（kind=`elim`）赛程由系统自动生成——按种子算法（`buildElimPlan`）、按跨组模板（`buildCrossPlan`）或按取人区间（`takeRangePool`）；小组赛完赛后还会自动补生成后续淘汰阶段。展示上，两回合被渲染成两条独立行。

目标：

1. 淘汰赛不再自动生成赛程；首轮由管理员在管理端点选配对、**手动落位**。
2. 后续轮次由系统按首轮场次数铺空壳，胜者由现有晋级器自动回填（晋级逻辑不改）。
3. 公开赛程页两回合**按回合分区块**展示；未定席位显示候选队名占位。

非目标：

- 不改晋级器 `buildAdvanceStmts` 的判定逻辑。
- 不改小组/循环阶段的编排与自动生成。
- 不引入对阵树/连线图；不做拖拽。

## 3. 设计

### 3.1 管理端淘汰赛视图（分层列表）

赛程页里，淘汰阶段（kind=`elim`）改为分层列表渲染，其余阶段不动：

- 从上到下：【第 1 轮】（手动落位区）→【半决赛】→【决赛】，启用季军赛时决赛下方多一段【季军赛】。不画连线，行=**场次**（文案统一用「场次」）。
- 行内信息：对阵双方 / 比分（两回合制显示「首回合 x:y · 次回合 y:x · 总比分 A:B」）/ 晋级方高亮 / 徽章（进行中、轮空、弃权）。
- 空场次：`〔空〕点此落位（先点主队 → 再点客队）`。
- 后续轮次行：`待定（第 1 轮·场次 1 胜者）vs 待定（第 1 轮·场次 2 胜者）`；季军赛用「半决赛·场次 N 负者」。决出后自动换成队名。
- 首轮段落末尾：`〔＋新增场次〕`。
- 淘汰阶段移除「自动生成对阵」按钮；「清除赛程」（未开打时一键清空重摆）保留。

### 3.2 落位交互（点选配对）

点空场次 → 展开候选面板：

- 候选 = 本赛事全部参赛队（带分组字母）；来源阶段已完赛且能解析时，出线队置顶并加「出线」标记；解析不出就是普通列表，不阻塞落位。
- 先点主队 → 再点客队 → 「确认落位」；只选 1 队时可点「轮空」，落成单队场次（直接进下一轮）。
- 轮空的存储形态（晋级器唯一认可的轮空形态）：单行、`away_entry_id = null`、`winner_entry_id` = 已落该队、`note="轮空"`；轮空不铺第二回合。`start`/`finish` 对 `note="轮空"` 明确拒绝，快讯/统计排除轮空。
- 本轮已落位的队伍在面板里置灰（一队一轮只能一场）。
- 两回合制：落位后自动铺首回合/次回合两行（主客对调）；轮空不铺第二回合。
- 点已落位（未开打）的场次 = 重新编辑，可清除或改选。

### 3.3 首轮场次数与结构锁定

- 首轮场次数必须是 2 的幂（1/2/4/8/16，上限 16 场 = 32 队）；2 队直接决赛（1 场）也合法。
- 数量为 2 的幂时，系统自动铺后续轮次空壳（半决赛/决赛/季军赛，回合制按 `legs`/`final_legs` 配置）；凑不满的席位就是落「轮空」的位置。
- 数量不是 2 的幂时（如 3 场）：轮次标题旁提示「首轮场次数需为 2 的幂（当前 3 场）」；不铺后续轮次；**改回 2 的幂之前不能开打**（所有让场次进入进行中/已完赛的入口都会校验并拒绝）。
- 结构锁定：阶段内有场次开打/完赛后，禁止增删场次；但未落位的空场次仍可继续落位。
- 删除场次：可删空场次和未开打的已落位场次（连落位一起删），后面场次序号自动前移。
- ~~例外：轮空一旦已晋级到下一轮（下一轮已显示该队），不能单独清除，只能整段「清除赛程」重摆。~~ **（实现期作废）** 轮空产生的下游预填由结构重建统一清掉（空壳对齐时把 pending 行的 home/away/winner 置 NULL）并重跑幂等晋级器，因此轮空席位可以单独改位；真正的边界是「后续轮次已开打 → 首轮落位冻结」（`PUT/DELETE …/slots/:slot` 409）。
- 淘汰阶段的「回合制 / 决赛回合数 / 季军赛」配置在出现场次后锁定（要改先清除赛程）。
- 轮次与决赛归属：首轮 N 场（N = 2^k）＝满编 2N 队 → 总轮数 = log2(2N) = k+1；第 r 轮为决赛 ⟺ r = 总轮数，决赛取 `final_legs`，其余轮取 `legs`（沿用 `buildElimPlan` 既有语义 `worker/lib/seeding.ts:56-57`）。因此 N=1（2 队直接决赛）时总轮数 = 1，该场按 `final_legs` 铺行。
- 季军赛沿用既有守卫：总轮数 ≥ 2 才出现【季军赛】段（`worker/lib/seeding.ts:95` 的 `thirdPlace && rounds >= 2`）。
- 结构变化（未开打时增删首轮场次）：总轮数随之变化 → 重新判定决赛归属 → 对**未开打**的已落位场次重铺 leg 行（对阵与落位保留，只按新的 `legs`/`final_legs` 重建 leg 行；leg 行形状不变时原地 UPDATE 保留 `match.id`，因为 `tactic_submission.match_id` 是 `ON DELETE CASCADE`，删行会连带删战术提交）；后续轮空壳整段重建；随后补跑一次幂等晋级器（轮空即时晋级的回填／回滚）。

### 3.4 后端接口与行为

新接口（命名可微调；实际挂在 `/api/admin/tournaments/:id` 下，与现有手动落场端点同基址）：

| 接口 | 语义 |
| --- | --- |
| `POST /api/admin/tournaments/:id/stages/:stageId/slots` | 首轮新增一个空场次 |
| `PUT /api/admin/tournaments/:id/stages/:stageId/slots/:slot` | 落位/替换/清空（`{homeEntryId, awayEntryId}`；away=null → 轮空；全 null → 清空）；两回合自动建 leg1/leg2 |
| `DELETE /api/admin/tournaments/:id/stages/:stageId/slots/:slot` | 删除场次（未开打；已落位的连清除） |

- 端点范围：`PUT`/`DELETE …/slots/:slot` 只对**首轮**（`round = 1`）生效；后续轮次归晋级器所有。路由没有 `round` 参数，`:slot` 一律按首轮场次号寻址，因此对后续轮无从表达（不会误改后续轮），不存在的首轮场次号 → 404「首轮第 N 场不存在」。落位参数须成对给（`homeEntryId` + `awayEntryId`）：`awayEntryId = null` → 轮空；两者皆 null → 清空该场次；`homeEntryId = null` 且 `awayEntryId ≠ null` → 400。
- 校验：仅 elim 阶段；队伍须属本赛事；主队≠客队；同一轮一队只能一场；目标场次已开打 → 409。
- 配套守卫（场次行只由结构重建维护）：单场删除端点 `DELETE /api/admin/tournaments/:id/matches/:matchId` 对 elim 阶段 → 400「淘汰赛请在赛程页增删场次」（否则可单删两回合中的一条 leg 行，总比分算不出、对手席位永不填充）；淘汰阶段出现场次后回合制参数（`legs`/`final_legs`/`third_place`）锁定 → 改配置 400「该淘汰赛阶段已有场次，回合制参数已锁定（要改先清除赛程）」（同值重发不拦，「清除赛程」后放行）。
- 增删/落位/清空后：重算后续轮次空壳（2 的幂 → 重建；否则清掉空壳），未开打的已落位场次按新的决赛归属重铺 leg 行（形状不变时原地 UPDATE 保 `match.id`），随后补跑一次幂等晋级器（覆盖轮空晋级的回填与回滚）。上述操作只允许在未开打时，不涉及历史回填。（实现说明：`schedule.ts` 无审计写入惯例，故这些端点未写 audit。）
- 关闭淘汰赛自动生成：
  - `POST …/generate` 对 elim → 400「淘汰赛改为手动落位」；前端按钮移除。
  - 自动补生成（`buildAutoFillStmts`）跳过 elim 目标——小组赛打完后不再自动生成淘汰赛赛程，等管理员落位。
  - 取人区间/跨组模板不再驱动淘汰赛生成，只用来算「出线」标记。
- 晋级器 `buildAdvanceStmts` 一行不改：轮空、两回合总比分、点球决胜、季军赛（半决赛负者）逻辑全部复用。
- 出线标记数据：阶段数据附「出线队 id 列表」（best-effort——来源阶段完赛且来源配置可解析时算出；否则为空，UI 不显示标记）。

### 3.5 公开赛程页（/t/:id 赛程 tab）

- 两回合按回合分区块（仅两回合制的轮次分块；单场轮次不分）：
  - 同一轮下先【首回合】区块、再【次回合】区块；区块内每行 = 一场对阵（不再把 leg1/leg2 拆成两行）。
  - 【首回合】行显示该回合比分；【次回合】行显示次回合比分 + 总比分，晋级方在次回合行高亮。
- 候选队名占位：**由后端计算**并随公开赛程的场次数据下发（场次行增加 `homePlaceholder` / `awayPlaceholder`，仅空席位有值）。公开页按轮懒加载，后续轮占位依赖上一轮数据，纯前端算不出。逐席位规则：
  - 后续轮（round ≥ 2）席位 = 直接来源场次（同阶段 r-1 轮 slot 2s-1 / 2s；季军赛取两场半决赛）中已存在的队名，用「/」连接；只有一支队已知（如来源是轮空）就只显示该队名。两回合场次的**次回合行主客对调**（leg2 的主队来自下一来源场次，与落位/晋级器同口径）。例：第 1 轮 1vs2、3vs4 打完前，下一轮显示「1/2 vs 3/4」。
  - 首轮席位 = 来源解析出的候选集合：跨组模板 → 该席位对应 token 的球队（名次已定 → 队名；否则 token 摘要，如「A 组第 1」）；取人区间 → 区间内球队（≤2 支列队名，>2 支显示「阶段 N 第 from–to 名」，避免噪声）；无来源 → 「待定」。
  - 来源阶段**尚未全部完赛**时名次不作数（与赛程生成同口径）：首轮一律不下发占位（连「A 组第 1」这类模板摘要也不给，席位还没定，标了反而误导），管理端也不给「出线」标记。
  - 算不出（来源没落位/没完赛/来源场次不存在）就回退「待定」。
- 轮次名沿用现状（1/4 决赛、半决赛、决赛），不改。
- 淘汰阶段尚无任何场次时，显示一行灰字「赛程待编排」。
- 「进行中」区、行内链接、比分样式保持现状。

## 4. 兼容与边界

- 存量数据：生产两个淘汰阶段零场次，无迁移负担。若测试环境留有旧自动生成的场次：未开打 → 可「清除赛程」重摆；已开打 → 只读保留，晋级器继续工作。
- 小组赛完赛后的自动补生成链路被替换：管理员落位后才出现淘汰赛赛程。取人区间/跨组模板配置保留在阶段配置里（仅用于「出线」标记与首轮候选）。
- 两处生产的形态都能落：附加赛 = 首轮 1 场直接决赛；冠军杯复赛 = 首轮 4 场（8 队）→ 半决赛 2 → 决赛 1。
- 轮空只出现在首轮（凑不满的席位）；后续轮次由晋级器处理。
- 淘汰赛已开打后管理端视图只读，报分/改判/晋级照旧。
- 抽签、补全双循环等仅保留给小组/循环阶段，不受影响。

## 5. 测试范围（验收）

- 后端：slots 增/删/落位/落轮空；校验 409（非 2 的幂开打、已开打改结构、跨赛事队伍、同轮重复、主队=客队）；`PUT/DELETE` 只按首轮场次号寻址（后续轮无从表达，不存在 → 404）、`home=null & away≠null` 400；generate 对 elim → 400；单场删除端点对 elim → 400；淘汰阶段出现场次后回合制参数锁定（改配置 → 400，清除赛程后放行）；自动补生成跳过 elim 目标；1/2/4/8/16 场次下后续轮次空壳布局（含 N=1 直接决赛取 `final_legs`、结构从 1 场改 4 场时 leg 行重铺）；开打闸门覆盖 start 与 finish/快速报分两个入口；占位计算（后续轮「1/2 vs 3/4」、区间 >2 支回退「第 X–Y 名」、来源阶段未完赛/回退「待定」）；晋级器回归（轮空晋级、两回合总比分、点球、季军赛）。

## 6. 已确认的决策记录

- 占位内容 = 候选**队名**（如「北京/上海 vs 广州/深圳」）。
- 首轮场次数 = **2 的幂 + 轮空**；6 队 → 首轮 4 场（2 实打 + 2 轮空）→ 半决赛 2 → 决赛 1。
- 落位候选范围 = **全部可点 + 出线标记**（解析不出不阻塞）。
- 管理端视图 = **分层列表**（排除树状连线图）；公开页两回合 = **回合分区块**（排除相邻行加标签、对局大卡）。
- 占位由**后端计算下发**（公开页按轮懒加载，前端拿不到上一轮数据）；取人区间来源候选 >2 支时回退概括「阶段 N 第 from–to 名」，避免逐席位铺队名炸屏。
- 决赛归属沿用既有语义 `r = 总轮数 → final_legs`（故 2 队直接决赛用 `final_legs`）；季军赛沿用总轮数 ≥ 2 守卫。
- 未开打时增删首轮场次 → 已落位场次**保留对阵、重铺 leg 行**（不要求重新落位）。
